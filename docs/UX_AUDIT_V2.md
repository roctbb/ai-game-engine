## Что исправлено при сверке

- В лобби отделены текущие матчи и прошедшая история. У обычной записи истории убрана плашка «Завершён»; ошибки выделяются отдельно. Сохранены фильтры при обновлении и возврате из разбора.
- Просмотр текущих матчей имеет один переключатель и одно игровое поле. В скрытых вкладках iframe больше не запускается. Полное публичное лобби доступно авторизованному зрителю без добавления в состав.
- Разбор попытки получил шапку с автором/временем, навигацию между попытками, время снимка и явное «только чтение». Ошибка заметна у файла, в левом поле редактора и над визуализацией.
- Обновления собственного запуска не подменяют открытую попытку ученика. Повтор поля из разбора возвращает собственный редактор. Незавершённая загрузка снимка не возвращает старый режим после выхода из разбора.
- В повторе матча управление перенесено под поле; повторяющиеся сводки заменены компактной таблицей. Состав виден до появления счёта; сущности карты не считаются игроками, старые имена сопоставляются с участниками без дублирования. Сохранены исходники, события, ошибки и технический перезапуск в меню.
- В турнире убраны крупные декоративные счётчики; вкладки вынесены отдельно, итоговая таблица занимает ширину страницы. Модерация осталась в меню участника.
- Компактные кнопки, select и меню имеют высоту 32 px, обычные — 36 px, мобильные — минимум 44 px. Исправлены контраст ошибочной строки кода и сообщения недоступного сервиса в тёмной теме.
- Поле крестиков-ноликов вписывается в высоту/ширину панели при открытии кода; служебные сообщения renderer скрыты. Escape передаётся из игрового iframe.

## 2026-11-12 — производительность, ошибки ботов и ничьи

По SSH подтверждён повторный разбор каталога на пути просмотра игры. Разбор манифестов и проверка файлов выбранного пакета кешируются по ревизиям файлов; независимые регрессионные проверки покрывают изменение, добавление и удаление файлов, а также защиту кеша от изменения возвращённой модели. В production после прогрева поиск и загрузка манифеста в среднем занимают 6,184 мс за 50 вызовов. Это измерение конкретного пути Python, не полного HTTP-запроса. Heartbeat и подсказка запуска подбора больше не ждут блокировку matchmaker; занятый такт откладывается, обычные изменения состава остаются под блокировкой. Отдельно сохранено снятие игрока после десяти минут офлайна при возвращении.

Только в пакете крестиков-ноликов разрешён `random`. Проверены импорт с псевдонимом, импорт отдельной функции, воспроизводимость, первый ход в центр, ошибка импорта, исключение внутри функции и неверные координаты. Ошибка пропускает ход; первый свободный ход больше не подставляется. В просмотре видны сообщение и переход к строке сохранённого исходника. Старые ошибки компиляции также доступны своему автору. Диагностика соперника ученику не выдаётся.

Ничья даёт по 0,5 очка. Новое правило турнира ограничивает серию тремя партиями: код сохраняется, знаки меняются, после третьей ничьей оба проходят. Финал без исключений заканчивается совместным первым местом. Все партии и общий счёт сохраняются в JSON раунда и архиве; изменение схемы БД не требуется. Таблица не считает ничьи поражениями или победами и не складывает накопленные суммы повторно.

Сквозной прогон через локальный API с настоящим игровым движком прошёл от запуска до архива в режимах `instant` и `sequential`; в каждом сохранились три ничейные партии и по 1,5 очка. Браузерная проверка за преподавателя и ученика покрыла просмотр всех партий, итоговую таблицу, архив, выбор правила ничьей и неизменяемость исходника матча при обновлённом рабочем черновике. Рабочий редактор сохраняет изменения после перезагрузки; разбор не принимает ввод. Дополнительная живая серия проверена с поздним входом: зрители попали на уже заполненное поле, автоматически перешли к следующим партиям и увидели результат только после их показа. Проверены ширины 1440/1200 и 390 px, диалог по центру, отсутствие горизонтального переполнения и ошибок JavaScript. Этот дополнительный проход использует in-memory API и выполнение движка через internal API, а не новый прогон полного Docker-стека.

Финальные проверки: backend — 415 passed, 6 skipped; frontend — 47 passed, TypeScript и production build успешны; Ruff и `git diff --check` без замечаний. UX-граф, описание экранов, спецификация и руководство игры обновлены.


## 2026-11-12 — подпись ничьей при равных половинных очках

В лобби, истории и разборе крестиков-ноликов счёт 0,5 у каждого участника означает «Ничья», даже если старая запись содержит одного победителя или не содержит `metrics.draw`. В истории убрана победная отметка; собственный результат подписан как ничья. В разборе дробные очки не округляются до целых, места у участников ничьей одинаковы. В сетке турнира исход партии отделён от решения о проходе дальше.

Проверки: 52 frontend-теста и production build прошли. В браузере за учеником проверены история и разбор локальной записи с половинными очками, отсутствующим флагом ничьей и ошибочно сохранёнными победителем/местами, а также сетка архива из трёх ничьих. В разборе видны «Ничья», 0,5 у обоих и равные места; в истории нет победной отметки. Ошибок JavaScript нет. Производственные записи для проверки не менялись.


## 2026-11-12 — старые накопленные победы в тренировке

Проверка серверной статистики обнаружила сохранённые прибавки побед за ничьи до исправления выбора единственного победителя. Новый расчёт матчей уже не выбирает победителя при равенстве, но удалённые тренировочные записи сохраняются в `cumulative_stats_by_team`, поэтому старые прибавки остались после обновления кода.

Для лобби крестиков-ноликов подготовлена поправка по резервной копии до изменения очков за ничью. Тогда победа давала 1, ничья и поражение — 0; у проверяемых строк число оценённых матчей совпадает с числом игр, сумма очков целая. Поэтому разность между старым счётчиком побед и суммой очков точно определяет ошибочную прибавку. Поправка вычитает только эту разность из текущих побед, сохраняя последующие результаты. План затрагивает семь участников и 72 ложные победы. Для проверенного ученика: 20 → 6 побед, 40 игр и 6 очков, среднее 0,15. Старые очки остаются по действовавшим тогда правилам; число ничьих удалённых матчей из агрегатов восстановить нельзя.

Операция использует общую Redis-блокировку лобби и блокировку строки PostgreSQL, проверяет исходные данные и сохраняет протокол до/после. Повторное применение защищено отдельным журналом операции; резервная копия БД создаётся до применения. Среднее в интерфейсе больше не округляется до одного знака. Проверки: 52 теста frontend и production build прошли, добавлена проверка отображения 6/40 как «0,15».
