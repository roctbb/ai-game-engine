# Арена: внедрение UX V2

Реализован рабочий интерфейс «Тихой аркады» на существующих Vue/FastAPI механизмах запусков и неизменяемых снимков.

## Маршруты и роли

- `/lobbies` — открытые публичные лобби для всех ролей. Материалы и API каталога доступны преподавателю и администратору по `/tasks`; прямые ссылки `/tasks/:gameId` доступны ученикам.
- `/lobbies?all=1` — управление всеми доступными преподавателю лобби из меню профиля.
- `/tasks/:gameId` — полное условие слева; продолжение, личный результат, лидерборд и попытки справа. У преподавателя — фильтр попыток по ученику и переход к настройкам метаданных задачи.
- `/tasks/:gameId/run` — редактор слева (52% по умолчанию), поле справа, одна панель действий; условие/API заменяет поле и закрывается Escape. На телефоне переключаются код и поле. Ctrl/Cmd+Enter запускает попытку.
- `?inspect_run=...` — неизменяемый разбор с временем снимка, предыдущей/следующей попыткой и возвратом в исходную историю с её фильтрами. Свой исходник можно взять в черновик с отменой замены.
- `/lobbies/:lobbyId` — игры на всю ширину, отдельные вкладки участников и таблицы (`?tab=participants`), условия и архива. Текущий турнир открывается из баннера на полную страницу соревнования; создание ведёт туда же. `/lobbies/:lobbyId?tab=code` — компактное рабочее место через «Мой код»; переход в очередь сохраняет код. Страница сохраняет выбранную вкладку при обновлении.
- `/competitions/:competitionId` — матчи, сетка, таблица; фильтры всех/своих матчей и участника. Следующий раунд запускает преподаватель. Решение ничьей требует явного выбора участников.
- `/lobbies/:lobbyId?tab=game&match=…` — отдельный просмотр всех текущих матчей с переключателем; iframe монтируется только в просмотре или коде, а не в скрытых вкладках. Прошедшая история отделена от текущих матчей и хранит фильтры в query.
- `/runs/:runId/watch` — просмотр любого доступного турнирного матча. Ученик открывает только свои исходники и диагностику; преподаватель — исходники участников. Повтор вне трансляции можно свободно перематывать. Управление находится под полем, справа компактная таблица; разрешённый исходник заменяет таблицу. Полный экран возвращается Escape, в том числе из iframe. Публичный тренировочный матч доступен авторизованному зрителю без вступления в заполненное лобби; для закрытого нужна принадлежность к лобби. Права на код и логи остаются отдельными.

## Очередь и турнир

Изменение состава, готовности, присутствия, настроек, очистка истории и подбор сериализованы одним Redis-замком лобби. Повторный вход в замок внутри операции разрешён; локальные потоки используют RLock. Это сохраняет изменения участника при одновременной записи API и отдельного matchmaker. Конкурентный тест использует раздельные копии моделей, как в SQL-хранилище; Docker-проверка покрывает двенадцать одновременных вступлений во время настоящего матча.

Присутствие определяется по обращениям к лобби (онлайн в пределах 20 секунд); обновление сохраняется не чаще одного раза в 10 секунд. В скрытой вкладке клиент останавливает поток присутствия. Есть отдельный `POST /lobbies/:id/presence` для контекстных клиентов.

В подборе участвуют готовые игроки очереди, онлайн-игроки имеют приоритет. Для запуска достаточно активного зрителя лобби: ему не требуется вставать в очередь. Присутствие просмотра разделяется через Redis между процессами API и отдельным matchmaker. Недостающий состав, включая неполную последнюю группу, дополняется случайными офлайн-участниками с совместимым сохранённым кодом только до минимума игры. Без активного просмотра новые матчи не запускаются. У обычного игрока после 10 минут офлайна готовность снимается; возвращение не восстанавливает её. Добавленные администратором боты сохраняют готовность, но играют только при активном просмотре. Явная повторная постановка игрока в очередь начинает новый период ожидания.

Состав турнира фиксируется перед стартом: очередь или ручной выбор. Для старых клиентов сохранён режим `all`; новый интерфейс явно передаёт `queue` или `selected`. После фиксации присутствие и новые подключения состав не меняют.

Расчёт результатов не запускает следующий раунд. Длительность просмотра повтора не задерживает готовые результаты. Платформенный сбой останавливает продвижение; повтор создаёт новые запуски с прежними снимками кода и seed, сохраняя неудачные запуски. Турнирные матчи не смешиваются с тренировкой.

Архив хранит отдельные турниры с датой, составом, раундами и результатами. Для матчей более пяти игроков состав раскрывается; в строке остаются число игроков и личный результат.

## Общий отсчёт первого показа

Для турниров добавлен `presentation_mode`: `instant` (совместимость существующих соревнований и API) и `sequential`. Новый диалог по умолчанию предлагает последовательный показ. Миграция `0018_competition_presentation` добавляет колонку с безопасным значением `instant`; расписание каждого матча сохраняется в JSON раунда. Вычисления выполняются параллельно, а показ идёт по очереди после готовности раунда, по 500 ms на кадр и с 2 секундами на результат. Результаты матчей фиксируются при достижении их времени раскрытия, а не при завершении расчёта. Поток соревнования согласует состояние на каждом такте; нового раунда без команды преподавателя не создаёт.

Результат запуска сохраняется раньше отдельной записи повтора. `GET /replays/runs/:id` в этом промежутке собирает тот же повтор из результата основного запуска без записи в базу; запрос вторичного запуска использует основной. Проверки прав и фильтрация чужой диагностики применяются к обоим путям. Для аварийного или отменённого запуска просмотр не запрашивает несуществующий повтор.

`GET /runs/:id/watch-context` возвращает `server_now`, `server_received_at` и `first_show` (`started_at`, `frame_ms`). Пустой `started_at` означает ожидание готовности состава. Для текущей тренировки начало берётся по последнему завершившемуся запуску общей пачки; у турнира — по запускам конкретного матча. Старые timestamps без часового пояса нормализуются как UTC.

Клиент привязывает ответ к `performance.now()`, вычитает время обработки запроса на сервере из сетевой задержки, учитывает время загрузки и вычисляет текущий кадр по прошедшему времени. Первый показ не использует пошаговый таймер обычного повтора или личный preset скорости. После скрытой вкладки и загрузки renderer выбирается актуальный кадр; после последнего кадра показ не зацикливается. Дополнительный запрос контекста нужен только в ожидании начала и при возврате во вкладку, а не для каждого кадра.

Общий отсчёт применяется и в iframe лобби, и на полной странице матча. Родительская таблица берёт состояние от показанного кадра: готовые финальные очки и карточка победителя не появляются раньше времени. Обычный архив сохраняет паузу, скорость, перемотку и начало с первого кадра. Схема базы не меняется.

## Стиль и ошибки

Общие токены в `frontend/src/styles/arena.css`: Golos Text, JetBrains Mono, спокойные нейтральные поверхности, синий акцент, жёлтая деталь бота. Бот используется в навигации и favicon; змейка — в активных загрузках. Поддерживаются системная тёмная тема и reduced motion.

Ошибка кода отличается от ошибки запуска: значок × в левой колонке истории, текстовый статус, диагностический блок над полем, переход к строке неизменяемого исходника и красное выделение строки с номером. Полная диагностика раскрывается отдельно.

Поля присутствия сохраняются в существующем JSON участников лобби, поэтому отдельная SQL-миграция не нужна. Старые записи читаются без новых полей.

## Исключено из этого этапа

По решению пользователя передача оценок в codingprojects отложена. Вход через codingprojects сохранён. Новые шкалы оценивания и серии скрытых проверок не создаются: результат и критерии остаются контрактом игрового движка; редактор метаданных управляет существующими настройками задачи.

## Проверка

- Pytest: API, доменные сценарии, SQL и сервисы scheduler/worker/builder. Vitest и production build с проверкой TypeScript.
- Playwright: экраны гостя, ученика, преподавателя и администратора на компьютере и телефоне, в светлой и тёмной темах. Проверены контраст, переполнение, тени кнопок и переходы между экранами; отдельно — настройки задачи, меню с клавиатуры, диагностика попытки и просмотр матча.
- Полный стек Docker в Colima с локальной копией серверной базы: задача → реальный запуск → ошибка → разбор; готовые боты начинают играть при входе зрителя; при отсутствии зрителей новые матчи не создаются; два раунда турнира с ручным продвижением, архивом и просмотром матчей без раскрытия чужого кода.

Для повторения сквозной проверки на изолированном стеке с включённым dev-login и автоматическими воркерами: `python3 scripts/e2e_arena_journeys.py`. Порты можно переопределить через `--backend`, `--scheduler` и `--worker`. Скрипт создаёт тестовых пользователей и лобби и оставляет завершённый турнир для просмотра.


## Контекст редактора и автоматический вход

Рабочее место лобби выбирает запуск по собственному `my_team_id`, отдельно от зрительского `match` и запасного последнего запуска. При отсутствии своего запуска открывается справка; при входе в редактор очищается только параметр `match`, остальные фильтры сохраняются. В турнире выбор ограничен текущим показом и раскрытыми собственными матчами. Статистика поля берётся из фактически показываемого матча.

Если `/auth/options` разрешает Geekclass и запрещает dev-login, `/login` автоматически переходит на `/api/v1/auth/login?next=…` после завершения проверки сохранённой сессии. Ошибка загрузки настроек или callback запрещает автоматический переход. Неудачный callback возвращает `/login?next=…&auth_error=geekclass`; успешный сохраняет query/fragment назначения и заменяет прежний `session_id`.

### Очередь дуэлей и просмотр из плашки

Ожидающая дуэль представлена двумя сохранёнными запусками `created` с общим `duel_id` и снимками кода, выбранными при запросе. Matchmaker восстанавливает очередь из БД, проверяет свободную пару и приоритет перед обычной тренировкой; интерфейс не блокирует запрос по `playing_team_ids`, поскольку это поле включает первый показ и результат. Статус группы `queued` остаётся в текущих запросах, но выводится отдельным списком и не раскрывает итог. Экран разбора ожидания автоматически получает запуск и общий первый показ. Плашка состояния выбирает собственный текущий запуск и содержит кнопку «Смотреть». Действия просмотра используют те же компактные кнопки с рамкой, что и дуэль.
