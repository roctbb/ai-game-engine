# Крестики-нолики — четыре в ряд

## Актуальные правила

Версия пакета — **2.0.0**. Два игрока по очереди занимают свободные клетки поля **5×5**. Крестики ходят первыми. Побеждает первый, кто соберёт **не менее четырёх своих знаков подряд** по горизонтали, вертикали или диагонали. Отрезок может начинаться в любой клетке, в том числе на диагонали, не проходящей через центр. Полное поле без победной линии даёт ничью.

Победа — 1 очко, ничья — по 0,5, поражение — 0. Ошибка Python или недопустимый ход пропускают ход и показываются игроку; предел — 50 ходов с учётом пропусков. `random` разрешён. Функция и координаты прежние: `make_choice(field, role)` возвращает `(x, y)`, `field[x][y]` содержит `0`, `1` или `-1`.

Технический ID `ttt_connect5_v1` сохранён: переименование разорвало бы существующие связи с лобби, кодом и обработкой ничьих в турнирах. Число в ID больше не описывает длину победной линии. Правила определяются версией пакета.

Инструкция ученику находится в `games/tic_tac_toe/player_guide_ru.md`, демобот — в `games/tic_tac_toe/examples/connect4_balanced.py`. Он сначала завершает свою четвёрку, затем блокирует четвёрку соперника, затем выбирает клетку по простой оценке. Это учебная стратегия, не гарантия оптимальной игры.

## Разовый переход с пяти на четыре

По согласованию с владельцем старые результаты не переносятся в новую таблицу. Команда `scripts/upgrade_tic_tac_toe_connect4.py` в одной транзакции:

- удаляет запуски, повторы, записи исполнения матчей и завершённые соревнования только `ttt_connect5_v1`;
- обнуляет накопительную статистику его лобби и ссылки на последний набор матчей;
- переводит существующие лобби на версию 2.0.0;
- сохраняет состав лобби, очередь, настройки, рабочие области, пользовательский код и снимки кода;
- обновляет стандартных системных ботов только при совпадении SHA-256 с неизменённым демоботом версии 1.0.0. Пользовательские и отредактированные преподавателем исходники сохраняются целиком.

Другие игры и их статистика не затрагиваются. Если уже появились матчи версии 2.0.0, повторный сброс запрещён. При активном запуске или незавершённом соревновании команда прекращает работу без удаления.

Порядок развёртывания:

1. Сделать и проверить резервную копию PostgreSQL, сохранить образы предыдущей версии.
2. Собрать новую версию API и matchmaker. Остановить подбор, перевести исполнителей в draining, дождаться завершения заданий. Остановить API, чтобы запрос просмотра не создал новый матч во время перехода.
3. Выполнить команду ниже без `--apply`: она загрузит новый каталог и покажет план очистки. В окружении должны быть production-настройки PostgreSQL, Redis и путей пакетов. Не выводить содержимое переменных окружения.
4. Выполнить ту же команду с `--apply` после `python -`. Сохранить отчёт рядом с резервной копией.
5. Запустить API и matchmaker новой версии, восстановить прежние статусы исполнителей. Проверить правила, нулевые показатели до первого нового матча и неизменность состава/кодов игроков. Выполнить контрольный матч по новым правилам.

Из корня репозитория на сервере:

```sh
docker compose -f compose.yml -f compose.production.yml --env-file .env.production \
  run --rm -T --no-deps backend-api python - \
  < scripts/upgrade_tic_tac_toe_connect4.py
```

Это разовая операция обслуживания, **не** миграция Alembic и **не** обработчик старта приложения. Схема БД не меняется. Для отката удалённых результатов нужна резервная копия; обычный перезапуск ничего не обнуляет.
